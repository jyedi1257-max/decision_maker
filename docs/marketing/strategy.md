# 홍보 전략 (한 장)

마지막 고침: 2026-09-26 · 다음에 고칠 때: 테스터 가입 수를 받으면

## 지금 어디쯤인가

- 1.0 AAB(서명 전)를 대표에게 넘김. 대표가 서명해 Play 비공개 테스트에 올릴 예정
- **확인 안 된 것**: 개발자 계정 인증 완료 여부, 비공개 테스트 트랙 게시 여부, 테스트 참여(옵트인) 링크 유무
- 정식 공개 조건: 테스터 **12명 이상이 14일 연속** 옵트인 상태 유지 → 그다음 프로덕션 액세스 신청
  ([Play Console 고객센터](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko), 2026-09-26 확인)
- 스레드 계정은 오랜만에 다시 시작하는 상태. 팔로워 수·반응 수치는 아직 받은 게 없다

## 단계

### 1단계 — 테스터 20명 (지금 ~ 14일 조건 충족)

**목표**: 구글 그룹 가입 → 옵트인까지 마친 사람 **20명**. 12명이 필수이고, 중간에 빠지는 사람을 감안해 8명을 더 둔다.

| 무엇 | 기준 |
|---|---|
| 그룹 가입 수 | 20명 |
| 옵트인(테스터 되기) 수 | 20명. 이 중 12명 이상이 14일 연속 유지 |
| 14일 시계 시작 | 12번째 사람이 옵트인한 날 = D-0. 그날을 `log.md`에 적는다 |
| 피드백 | 한 줄 의견 5건 이상. 프로덕션 신청서가 "테스터 피드백 요약"과 "그걸 보고 무엇을 고쳤는지"를 묻는다 |

프로덕션 신청서는 모집이 얼마나 쉬웠는지, 테스터 참여도, 받은 피드백 요약, 그걸로 바꾼 점을 묻는다.
테스터 수가 모자라거나 **참여가 부족하면** 테스트를 더 하라는 답이 올 수 있다
([고객센터](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en), 2026-09-26 확인).
그래서 "설치만 해주세요"가 아니라 **"고민 하나를 끝까지 적어봐 주세요, 한 줄 의견 주세요"**까지 부탁한다.

**순서**

1. 대표가 구글 그룹을 만든다 (`tester-setup.md` 1장). Play 심사를 기다리지 않고 **그룹 가입부터 먼저 받는다**
2. 스레드 모집 글 (9/28) + 지인에게 1:1로 직접 부탁 (같은 글 파일 아래에 카톡용 문장 있음)
3. Play에서 비공개 테스트가 '게시됨'이 되면 옵트인 링크가 생긴다 → 그룹에 공지 한 번, 모집 글 첫 댓글을 고친다
4. 가입자가 **10/5까지 12명이 안 되면** 아래 '보조 채널'을 연다

### 2단계 — 출시 직전 분위기 (14일 진행 중 ~ 프로덕션 승인)

- 테스터 의견과 그걸로 고친 것을 스레드에 짧게 쓴다 ("테스터 한 분이 ○○가 헷갈린다고 해서 이렇게 바꿨어요").
  신청서에 쓸 기록도 되고, 만드는 과정을 보여주는 글도 된다. 인용은 본인 동의를 받은 것만
- 주 2~3회. 만든 이유(진로상담에서 쓰는 의사결정 표에서 출발), 일부러 뺀 기능, 화면 디테일 번갈아
- 인스타 릴스·유튜브 쇼츠는 이때 시작해도 늦지 않다. 36초 영상(`docs/promo/decision-note-promo.mp4`)을 그대로 쓸 수 있다
- 그룹 멤버에게 "출시되면 한 번 알려드릴게요"라고 미리 말해 둔다

### 3단계 — 출시 주간

- 스레드: 출시 알림 + 스토어 링크 + 36초 영상. 테스터에게 고맙다는 글
- 그룹에 출시 알림 한 번 (그룹 메일)
- GeekNews **Show GN**, 디스콰이엇에 제품 소개 (아래 채널 표 참고 — 바로 설치할 수 있는 링크가 있을 때 올리는 게 규칙에 맞다)
- 평점·후기는 **대가 없이, 솔직하게** 부탁만 한다. 보상을 걸거나 대신 써주지 않는다

### 스레드 관행 — 조사한 것 (2026-09-26 검색, 단정하지 않음)

- **글자 수 500자, 주제 태그는 한 글에 1개**, 태그도 500자에 포함된다는 정리가 많다
  ([Hashtag Tools](https://hashtagtools.io/blog/threads-tags-vs-hashtags-one-topic-tag-2026), [ThreadsTools](https://threadstools.app/guides/threads-character-limit-and-formatting)). 공식 도움말 원문은 확인 못 함
- **링크**: 인스타그램 대표 애덤 모세리가 2025년 6월 "링크가 제대로 순위에 반영되도록 손봤다"고 했다는 보도
  ([Social Media Today](https://www.socialmediatoday.com/news/meta-says-link-posts-ranked-properly-threads-reach/750126/)).
  그래도 본문엔 이야기, 링크는 첫 댓글에 두는 습관이 여전히 흔하다는 정리도 있다 ([HeyOrca](https://www.heyorca.com/blog/threads-social-news)).
  → 우리는 링크가 3개(그룹·옵트인·스토어)라 **어차피 첫 댓글이 읽기 편하다**. 도달 때문이 아니라 가독성 때문에 첫 댓글에 둔다
- **올리는 시간**: "평일 오전 10~12시, 저녁 7~9시, 화~목"을 권하는 글이 있으나
  ([Viraly](https://viraly.io/blog/best-time-to-post-on-threads)) 한국 기준 자료가 아니고 계정마다 다르다.
  → 1주차 세 글을 **서로 다른 시간대**(월 저녁 / 수 점심 / 금 저녁)에 올려 우리 계정 숫자로 본다
- **답글**: 좋아요·답글·공유가 노출에 영향을 준다는 정리가 공통적이다 ([Outfy](https://www.outfy.com/blog/how-threads-algorithm-works/)).
  → 올린 뒤 첫 한 시간은 답글에 바로 답하고, 남의 글(1인 개발·생산성·결정 고민)에도 진짜 답글을 단다
